# 悦享互动宝 MVP v0.1 资源落地清单

## 1. 文档说明

本文档用于指导设计、开发、运营和 Codex 在执行悦享互动宝 MVP v0.1 改造时，明确需要准备的图片、图标、文案、动效、配置文件、音频、视频等资源。

本阶段资源目标不是追求视觉复杂，而是保证：

1. 用户能快速理解“积分、签到、互动任务、影视福利、会员、邀请、提现”。
2. 页面具备基本商业转化能力。
3. 资源可以低成本上线。
4. 关键资源支持 mock 替代。
5. 后续可平滑升级到独立游戏小程序。

## 2. 资源使用原则

### 2.1 统一风格

当前小程序视觉以白底、浅绿色、浅黄色、圆角卡片为主。MVP v0.1 建议继续沿用，不做大规模视觉重构。

建议主色：

- 主色：绿色，用于按钮、积分、确认动作。
- 辅色：黄色/金色，用于会员、积分、奖励。
- 背景色：浅灰、浅绿、浅黄。
- 警示色：橙色或红色，仅用于失败、冻结、提现异常。

### 2.2 统一表达

前台统一使用“积分”作为用户可理解的主概念。

避免在前台同时强提示：

- 余额
- 收入
- 现金
- 赚钱
- 回本
- 每日收益

推荐表达：

- 我的积分
- 可兑换金额
- 可提现积分
- 每日福利
- 互动任务
- 积分奖励
- 邀请好友得积分
- 会员解锁更多权益

### 2.3 MVP 资源优先级

资源分为：

- P0：MVP 必须。
- P1：建议上线。
- P2：后续优化。

MVP 阶段优先保证 P0 资源齐全。

# 12. 资源验收总标准

## 12.1 图片验收

1. 图片清晰，不模糊。
2. 文件体积适合小程序加载。
3. 不影响文字可读性。
4. 能适配主流手机屏幕。
5. 不包含侵权影视剧照、明星照片、平台 logo。
6. 不包含高风险收益承诺文案。

## 12.2 图标验收

1. 普通态和选中态区分明显。
2. 视觉风格统一。
3. 尺寸适合小程序使用。
4. 不使用未授权商业图标。
5. 不使用微信、抖音、快手、小红书等平台 logo 作为功能图标。

## 12.3 文案验收

1. 用户能快速理解功能。
2. 不使用“看广告赚钱”作为主表达。
3. 不写“稳赚”“回本”“躺赚”“日入”“最高赚 100”等承诺。
4. 会员权益表达具体。
5. 提现说明清楚。
6. 邀请规则清楚。
7. 广告表达统一为“完成互动”“领取奖励”“解锁权益”。

## 12.4 动效验收

1. 不影响页面性能。
2. 不强制依赖动效才能完成流程。
3. 动效失败时页面仍可正常使用。
4. 不使用现金雨、人民币掉落等强收益视觉。

## 12.5 音频验收

1. 默认可关闭或不强制播放。
2. 音量不刺耳。
3. 不影响用户完成任务。
4. 使用可商用音效。

## 12.6 配置文件验收

1. 关键业务规则不散落在页面代码中。
2. 后端配置优先，前端展示和后端规则一致。
3. 配置字段命名清楚。
4. 配置变更后不需要大面积改代码。
5. 支持后续 A/B 测试。

# 15. Codex 执行建议

如果由 Codex 执行资源落地，请按以下顺序处理：

1. 先扫描当前项目资源目录。
2. 判断是否已有 assets/images/icons/config/copy 等目录。
3. 如果没有，建议创建：

```text
assets/
  images/
  icons/
  sounds/
  animations/
config/
  points.config.json
  task.config.json
  member.config.json
  invite.config.json
  withdraw.config.json
  media-rights.config.json
  video.config.json
  copy.config.json
```

4. 优先落地配置文件和文案文件。
5. 图片和图标如果没有真实资源，先用 emoji、纯色卡片、系统图标或占位图替代。
6. 不要因为缺少图片阻塞功能开发。
7. 所有 mock 资源必须标记 TODO。
8. 文案不得出现高风险收益承诺。
9. 会员价格建议按配置读取，不要写死在页面。
10. 图片、音频、动效资源必须可替换。
