### 4.2 需求广场 / 积分悬赏

已把“求资源”包装为“发布资料需求 / 资料许愿”：

- 默认悬赏：`10` 积分。
- 发布后进入 `pending_review`。
- 审核通过后变为 `open`，进入需求广场。
- 审核拒绝、取消、过期时退回冻结积分。

后端状态流转：

```text

pending_review -> rejected
pending_review/open -> canceled
pending_review/open -> expired
any -> admin_deleted
```

## 6. 后续迁移建议

### 6.1 最推荐的新项目形态

把现有能力迁移成一个独立 H5 场景：

```text
登录
  -> 大搜索框
  -> 模糊搜索资料/工具/模板
  -> 摘要结果
  -> 登录后查看获取指引
  -> 积分/收藏/需求发布作为留存机制
```

小程序暂时不要继续承担“资源库”主场景。可以改成更轻的入口，例如：

- 每日任务和积分成长。
- 收藏提醒。
- 公众号/视频号收藏提醒。
- 资料需求发布入口。
- H5 链接复制入口。

### 6.2 小程序后续包装方向

小程序主体可以只做“互动宝助手”：

- 推荐：工具、模板、灵感卡。
- 需求：资料许愿和线索提交。
- 任务：签到、答题、收藏、反馈。
- 收藏：用户收藏的公众号、视频号、工具、资料摘要。
- 我的：积分、消息、反馈、账号。

不要在小程序首屏出现：

- 网盘链接
- 提取码
- 解压码
- 影视剧
- 看广告解锁资源
- 提现
- 二级分销
- 收益承诺

### 6.3 H5 后续最小开发清单

1. 新建 H5 远端仓库，提交 `h5-interactbao`。
2. 增加 `.env.example`：

```text
VITE_API_BASE_URL=https://api.lifelove.top
```

3. 后端新增真实搜索接口，例如：

```text
GET /netdisk/h5/search?keyword=xxx
```

4. H5 首页从 demoResults 切换为接口搜索。
5. 配置 H5 正式域名，例如：

```text
https://h5.example.com
```

6. 后台配置 `h5_base_url` 为正式域名。
7. 小程序详情页复制链接改为：

```text
https://h5.example.com/r/{resourceId}
```

6. 小程序只保留积分、任务、收藏、需求、复制 H5 链接。

## 10. 重要风险

- 小程序过审风险仍然存在，尤其是资源、网盘、影视、收益、分销相关表达。
- H5 独立后风险更可控，但仍需要内容审核、版权合规和敏感词过滤。
- 积分属于高风险数据，冻结、退回、发放必须保留流水和幂等 key。
- 任何上线结论都不能只看本地构建，需要确认后端部署、数据库迁移、H5 部署和小程序上传。
