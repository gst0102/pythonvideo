# 求资源悬赏闭环_测试清单与验收标准

## 功能核心目标

验证发布悬赏冻结积分、投稿、采纳发放、取消/过期退回形成完整闭环，且积分账户、积分流水、悬赏状态、前端展示一致。

## 测试范围

- 求资源发布
- 悬赏积分冻结
- 悬赏投稿
- 采纳投稿
- 取消/过期退回
- 我的求资源和我的上传展示
- 积分明细展示

## 关键风险点

- P0：重复采纳导致重复发积分。
- P0：取消/过期和采纳并发导致重复退回或重复发放。
- P0：积分余额和流水不一致。
- P0：积分不足仍能发布悬赏。
- P1：用户给自己的悬赏投稿。
- P1：投稿列表权限错误。
- P2：状态文案不清晰。

## 验收标准

- P0 用例全部通过。
- 同一悬赏无论重复请求多少次，只能发放或退回一次。
- 积分账户、积分流水、悬赏状态、前端展示一致。
- 未登录、非发布者、积分不足、自己投稿等异常路径都有中文提示。
- 不影响资源解锁、上传奖励、积分明细现有功能。

- 对采纳和取消接口增加重复调用测试。
