# 2026-06-05 异机构建与生产拉镜像方案

## 1. 目标

把当前生产部署从“生产机本地构建镜像”切换为：

1. 在网络更稳、带缓存的构建机上构建正式镜像
2. 给镜像打明确版本 tag
3. 推送到镜像仓库
4. 生产机只执行拉镜像和 `docker compose up -d --no-build`

这样可以避免生产机长时间卡在：

- Python 依赖下载
- Playwright Chromium 下载
- Docker BuildKit 长时间占用

## 2. 当前适用基线

- 后端仓库：`git@github.com:gst0102/pythonvideo.git`
- 发布分支：`feature/yuexiang-stage2-mvp`
- 当前部署收敛提交：`d76f644`
- 生产服务器：`81.70.84.35`
- 生产目录：`/opt/pythonvideo`

推荐镜像 tag：

```text
pythonvideo-app:stage2-d76f644
```

如果使用远端仓库，建议完整 tag：

```text
<registry>/pythonvideo-app:stage2-d76f644
```

## 3. 推荐架构

### 3.1 构建机职责

构建机负责：

1. 拉取 `feature/yuexiang-stage2-mvp`
2. 构建镜像
3. 推送镜像
4. 可选执行镜像自检

构建机应具备：

- 稳定外网
- Docker / BuildKit
- 足够的磁盘缓存
- 可以访问镜像仓库

### 3.2 生产机职责

生产机只负责：

1. 更新仓库到对应提交
2. 拉取明确 tag 的镜像
3. 执行 `docker compose up -d --no-build app`
4. 执行 Alembic 迁移
5. 执行健康检查

## 4. 构建机执行步骤

### 4.1 拉取代码

```bash
git clone git@github.com:gst0102/pythonvideo.git
cd pythonvideo
git checkout feature/yuexiang-stage2-mvp
git pull --ff-only origin feature/yuexiang-stage2-mvp
git rev-parse --short HEAD
```

预期应为：

```text
d76f644
```

### 4.2 设置镜像变量

```bash
export APP_IMAGE=pythonvideo-app:stage2-d76f644
export APP_VERSION=stage2-d76f644
export VCS_REF=d76f644
export BUILD_DATE=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
export PIP_INDEX_URL=https://pypi.org/simple
```

如果团队有正式镜像仓库：

```bash
export APP_IMAGE=<registry>/pythonvideo-app:stage2-d76f644
```

### 4.3 构建镜像

```bash
docker compose build app
```

### 4.4 构建后核对

```bash
docker images | grep pythonvideo-app
docker image inspect "$APP_IMAGE" --format '{{json .Config.Labels}}'
```

重点确认：

- 有 `org.opencontainers.image.version=stage2-d76f644`
- 有 `org.opencontainers.image.revision=d76f644`

### 4.5 可选本地冒烟验证

```bash
docker run --rm -p 18000:8000 "$APP_IMAGE"
curl -s http://127.0.0.1:18000/health
```

## 5. 推送镜像步骤

### 5.1 登录镜像仓库

```bash
docker login <registry>
```

### 5.2 推送镜像

```bash
docker push "$APP_IMAGE"
```

### 5.3 记录发布元数据

建议至少记录：

- Git 提交：`d76f644`
- 镜像 tag：`stage2-d76f644`
- 构建时间
- 构建机名称

## 6. 生产机发布步骤

### 6.1 更新仓库到对应提交

```bash
ssh ubuntu@81.70.84.35
cd /opt/pythonvideo
git fetch origin
git checkout feature/yuexiang-stage2-mvp
git pull --ff-only origin feature/yuexiang-stage2-mvp
git rev-parse --short HEAD
```

### 6.2 设置镜像变量

```bash
export APP_IMAGE=<registry>/pythonvideo-app:stage2-d76f644
export APP_VERSION=stage2-d76f644
export VCS_REF=d76f644
export BUILD_DATE=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
```

### 6.3 只拉镜像，不本地构建

```bash
docker pull "$APP_IMAGE"
```

### 6.4 重建应用容器

```bash
docker compose up -d --no-build app
```

### 6.5 迁移数据库

```bash
docker compose exec -T app alembic upgrade head
docker compose exec -T app alembic current
```

### 6.6 发布后检查

```bash
curl -s http://localhost:8000/health
curl -i -s http://localhost:8000/game/tasks/status
curl -i -s http://localhost:8000/admin/ad/game-bonus-config
docker compose ps
docker compose logs --tail=100 app
```

## 7. 验收标准

异机构建发布完成后，应满足：

1. 生产机不再执行 `docker compose build app`
2. `docker compose ps` 中 `app` 已切到新镜像
3. `/health` 返回 `200`
4. `/game/tasks/status` 未登录返回 `401`
5. `/admin/ad/game-bonus-config` 返回 `200`
6. Alembic 版本正确
7. 发布后不依赖容器内热同步代码

## 8. 回滚方案

### 8.1 镜像回滚

如果新镜像异常，直接回到上一个稳定 tag：

```bash
export APP_IMAGE=<registry>/pythonvideo-app:<previous-stable-tag>
docker compose up -d --no-build app
```

### 8.2 仓库回滚

如果需要同时回退仓库基线：

```bash
cd /opt/pythonvideo
git checkout backup/prod-pre-stage2-20260605
```

### 8.3 回滚后检查

```bash
curl -s http://localhost:8000/health
docker compose ps
```

## 9. 本次为什么推荐异机构建

当前生产机已经验证过以下问题：

1. 本地构建速度过慢
2. `playwright` 相关下载非常慢
3. 浏览器包下载体积大，生产机构建时间不可预测
4. 长时间占用生产机构建资源会增加发布风险

因此后续正式流程建议固定为：

```text
代码提交 -> 异机构建镜像 -> 推送镜像 -> 生产拉镜像 -> 无构建重启 -> 健康检查 -> 功能验收
```

## 10. 下一次发布建议

下次继续发布阶段二功能时，建议直接沿用这套模板：

1. 先完成代码 commit
2. 推送到 `feature/yuexiang-stage2-mvp`
3. 在构建机打新 tag，例如 `stage2-<sha>`
4. 生产只拉镜像
5. 发布后再按测试清单做功能验收
