# 权益金流水表测试清单与验收标准

## 核心目标

补齐权益金流水表，确保邀请权益金从入账、退款回收、提现冻结、提现成功、提现失败回滚全链路可追踪，且流水与 `users.balance / frozen_balance / total_income / total_withdrawn` 保持一致。

## P0 测试用例

| 编号 | 模块 | 测试名称 | 前置条件 | 操作步骤 | 预期结果 | 优先级 | 是否适合自动化 | 备注 |
|---|---|---|---|---|---|---|---|---|
| EQ-001 | 支付回调 | 月卡支付权益金入账流水 | 好友通过邀请关系购买月卡 | 触发支付成功回调 | 邀请人余额增加，生成 `invite_reward` 流水，金额与佣金一致 | P0 | 是 | 同订单重复回调不重复写 |
| EQ-002 | 退款回调 | 月卡退款权益金回收流水 | 月卡已支付且权益金已入账 | 触发退款回调 | 邀请人余额/累计收益扣回，生成 `refund_revoke` 流水 | P0 | 是 | 重复退款不重复扣 |
| EQ-003 | 提现 | 提现申请冻结流水 | 用户有可提现权益金 | 提交提现申请 | 余额扣减、冻结增加，生成 `withdraw_freeze` 流水 | P0 | 是 | 有处理中提现要拦截 |
| EQ-004 | 提现回调 | 提现成功流水 | 提现记录处理中 | 触发转账成功 | 冻结扣减、累计提现增加，生成 `withdraw_success` 流水 | P0 | 是 | 重复成功回调幂等 |
| EQ-005 | 提现回调 | 提现失败回滚流水 | 提现记录处理中 | 触发转账失败 | 冻结扣减、余额返还，生成 `withdraw_failed_return` 流水 | P0 | 是 | 重复失败回调幂等 |
| EQ-006 | 数据一致性 | 流水余额快照一致 | 完成入账、退款、提现链路 | 查询用户和流水 | 每条流水 after_balance/after_frozen/after_total_income/after_total_withdrawn 与用户状态变化一致 | P0 | 是 | 资金解释底座 |

## 验收标准

- 所有权益金金额变化必须写入权益金流水。
- 同一业务事件重复回调不得重复写流水、不得重复改余额。
- 流水必须包含事件类型、金额变化、变更后余额快照、关联业务类型和关联 ID。
- 退款后权益金不能继续留在用户可提现余额里。
- 提现成功/失败后流水和用户余额字段必须一致。
