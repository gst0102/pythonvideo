## 1. 功能核心目标总结

本 MVP 的核心目标是把产品主线从旧影视订阅能力调整为“网盘资料互助 + 积分解锁资源”。用户通过首页/资源列表发现资源，在资源详情页判断是否值得解锁，未解锁前不得看到完整网盘链接、提取码、解压码和备用链接；用户可通过签到、小游戏、广告任务、上传资源、补链、完成求资源等方式赚积分，并可通过积分解锁资源。

当前阶段重点是验收 `video-ts` 小程序静态原型主流程是否闭环，所有真实扣积分、真实冻结、真实发奖、真实支付、真实邀请奖励均不得在 mock 阶段被误认为已完成。后续接入真实 FastAPI 后端时，积分账户、积分流水、资源获取记录、上传审核、补链审核、求资源冻结/采纳/退回、支付回调、邀请奖励、二级收益、提现必须按 P0 风险验收。

当前阶段验收边界：

- 已纳入：小程序首页、资源列表/资源卡片、资源详情、mock 解锁、求资源发布、赚积分任务、上传资源、补链/投诉、收藏、本地 mock 状态。
- 未纳入真实完成：真实登录、真实资源 API、真实扣积分、真实流水、真实上传审核后台、真实求资源冻结、真实支付、真实邀请奖励、真实二级分销、真实提现。
- 必须提前定义：P0/P1/P2 验收标准、自动化建议、回归清单、上线前检查清单、Bug 单模板。

## 2. 优先级定义

| 优先级 | 判定标准 | 示例 |
|---|---|---|
| P0 | 不测可能造成链接泄露、积分/资金/奖励错发、重复领取、核心流程不可用、合规事故 | 未解锁泄露链接、重复解锁重复扣积分、支付回调重复发积分、任务重复领取 |
| P1 | 影响重要用户体验、关键状态展示、主流程转化，但不直接造成资产事故 | 上传状态显示错误、筛选不生效、页面跳转缺失、mock 状态刷新丢失需确认 |
| P2 | 轻微文案、样式、低频边界、视觉一致性问题 | 间距不一致、空状态文案不够清晰、按钮 hover/pressed 样式缺失 |

## 3. P0 高风险清单

| 风险编号 | 风险点 | 风险说明 | 验收要求 |
|---|---|---|---|
| R-P0-01 | 未解锁资源泄露链接 | 用户未解锁前看到完整网盘链接、提取码、解压码、备用链接 | 资源详情、列表、分享页、接口返回、页面缓存均不得泄露 |
| R-P0-02 | mock 解锁误导真实扣费 | 静态原型阶段“模拟解锁”被误解为真实扣积分 | UI 必须明确提示“静态原型，不真实扣积分”；积分余额不应伪造真实扣减 |
| R-P0-03 | 重复解锁重复扣积分 | 后续真实接口重复点击或重复请求导致多次扣积分 | 同一用户同一资源只能有一条有效获取记录，重复请求返回已解锁 |
| R-P0-04 | 上传审核绕过 | 用户上传资源后直接对外可见或直接发奖励 | 上传必须进入待审核；审核通过后才展示并发奖励 |
| R-P0-05 | 上传奖励重复发放 | 同一资源多次审核通过或重复回调导致重复奖励 | 审核奖励必须幂等，只发一次 |
| R-P0-06 | 补链审核绕过 | 补链提交后未经审核直接替换真实资源链接 | 补链必须待审核；审核通过后才更新资源链接和奖励 |
| R-P0-07 | 补链奖励重复领取 | 重复提交/重复审核导致补链奖励多次发放 | 同一补链记录只能奖励一次 |
| R-P0-08 | 求资源冻结异常 | 发布悬赏未冻结、重复冻结、采纳后重复发放、取消/超时未退回 | 冻结、采纳、退回必须有流水且余额一致 |
| R-P0-09 | 任务重复领取 | 签到、广告、小游戏、上传、补链任务可重复领取积分 | 任务状态必须防重复，后端接入后需幂等键和每日上限 |
| R-P0-10 | 小游戏/广告积分刷取 | 刷新、重复点击、重复广告回调重复发积分 | 同一局/同一广告事件只结算一次，每日上限生效 |
| R-P0-11 | 支付积分异常 | 支付失败发积分、支付成功未到账、重复回调重复到账 | 支付回调按订单号和交易号幂等；失败不发；退款有处理策略 |
| R-P0-12 | 邀请奖励/二级收益异常 | 邀请绑定错误、自邀、重复绑定、收益重复结算 | 邀请关系唯一；禁止自邀；真实支付订单才触发奖励 |
| R-P0-13 | 提现资产不一致 | 提现冻结、成功、失败退回与账户/流水不一致 | 可提现、冻结、已提现、流水必须一致 |
| R-P0-14 | 高风险内容合规 | 盗版影视、盗版课程、会员资源共享、高收益承诺文案 | 上线前必须人工审核种子资源、分类、文案和推广素材 |

## 5. 阶段验收标准

### 5.1 静态原型验收标准

静态原型可以进入下一阶段的最低标准：

- 首页、资源详情、求资源、赚积分、上传资源、补链/投诉、收藏、我的入口均可访问，无白屏和明显报错。
- 未解锁资源在任何卡片、详情未解锁区域、收藏页中都不显示完整链接、提取码、解压码。
- mock 解锁可在当前详情页展示链接，同时明确不真实扣积分。
- 上传资源提交后进入待审核 mock 状态，不直接变成公开资源。
- 补链/投诉提交后进入待审核 mock 状态，不直接替换链接或发奖励。
- 赚积分任务具备可领取、已完成、今日达上限状态，已完成/达上限不能重复领取。
- 求资源发布明确为 mock，不冻结真实积分；悬赏积分范围按 5-50 验收。
- 不出现“稳赚、返佣暴利、盗版影视、会员资源共享”等高风险文案。

### 5.2 后端接入验收标准

真实后端接入后，不满足以下任一项不得通过：

- 所有积分增减必须同时更新账户余额和 `points_ledger`，且有唯一幂等键。
- 资源解锁必须生成 `resource_access_records`，同一用户同一资源不得重复扣积分。
- 未解锁用户调用详情接口不得拿到链接、提取码、解压码、备用链接字段原文。
- 上传奖励、下载分成、补链奖励、求资源悬赏、支付充值、邀请奖励均必须防重复发放。
- 支付成功、支付失败、重复回调、退款场景必须全部覆盖。
- 邀请奖励和二级收益必须基于真实支付订单，不得基于 mock 任务或点击行为触发。
- 后台审核、投诉处理、补链审核必须有权限控制、状态流转和审计记录。

## 7. 回归测试清单

每次修改 netdisk 静态原型或后续资源域后，至少回归：

- 首页打开、资源卡展示、网盘标签、分类入口、赚积分入口。
- 底部 tab：资源、求资源、赚积分、收藏、我的均可跳转。
- 未解锁资源详情不泄露链接，模拟解锁后当前页面可展示 mock 链接。
- 已解锁资源详情可直接展示链接、提取码、解压码。
- 收藏/取消收藏，本地 storage 持久化，收藏页不泄露未解锁链接。
- 求资源发布必填校验、悬赏积分 5-50、提交后本地 mock 展示。
- 上传资源必填校验、提交后待审核、状态展示正确。
- 补链/投诉必填校验、提交后待审核、状态展示正确。
- 赚积分任务 claimable/completed/limited 状态，重复点击不能重复领取。
- 上传和补链提交后与赚积分任务状态联动。
- 我的页不出现旧业务高风险收益承诺文案。
- 蓝绿色视觉风格、底部安全区、滚动区域不被 tab 遮挡。
- 清空或异常 storage 后页面可恢复默认 mock 状态。
- 后续接后端后，必须额外回归积分流水、资源解锁幂等、支付回调幂等、邀请奖励、二级收益、提现。

## 8. 上线验收清单

上线前必须逐项确认：

- P0 测试用例全部通过，无未关闭 P0 Bug。
- 未解锁资源不会在前端页面、接口响应、分享页、缓存、日志中泄露完整链接。
- 资源解锁、上传奖励、下载分成、求资源冻结/发放/退回、补链奖励均有流水且幂等。
- 支付成功、失败、重复回调、退款后的积分和邀请奖励处理正确。
- 邀请关系不可自邀、不可重复绑定，一级/二级奖励比例正确且文案合规。
- 小游戏和广告奖励有每日上限，重复回调不重复发积分，广告统计一致。
- 上传、补链、投诉、后台审核权限和状态流转正确。
- 内容分类、种子资源、首页文案、推广文案已人工合规审核。
- 后台数据、前端展示、数据库流水、用户余额可对账。
- 开发 Codex 已输出自测报告，AI 测试官已输出验收报告；如有 Bug，已完成复测与回归。
- 用户作为最终负责人完成业务体验和上线确认。

## 9. 自动化测试建议

优先自动化以下场景：

- 未解锁详情页 DOM 不包含完整链接、提取码、解压码。
- mock 解锁前后页面状态切换。
- 收藏、任务、上传、补链本地 storage 状态写入和读取。
- 求资源悬赏积分边界：4、5、50、51、200。
- 上传/补链必填校验与待审核状态。
- 任务 claimable -> completed 后不可重复领取。
- 后端接入后：资源解锁幂等、积分流水一致、支付回调幂等、广告/小游戏重复回调、邀请关系绑定、二级收益计算。

## 11. 本轮 QA 结论

本文件为开发前/阶段性验收标准，不代表当前静态原型已通过最终验收。当前原型下一步建议先按本清单完成一次人工走查和 Codex 自测报告，再调用 `ai-qa-acceptance` 输出正式验收报告。

当前最需要优先确认的 P0/P1 项：

- 未解锁资源在所有页面不泄露链接。
- mock 解锁不真实扣积分，且文案不误导。
- 求资源悬赏积分范围统一为 5-50。
- 上传/补链/投诉必须是待审核状态，不直接生效。
- 赚积分任务已完成和达上限状态不能重复领取。
- 我的页和邀请收益文案不得出现高风险收益承诺。
