## 2. 当前问题

当前线上“代码状态”和“镜像状态”还没有完全收敛：

1. 生产仓库已经切到 `feature/yuexiang-stage2-mvp`。
2. 运行中的容器依赖过一次运行时文件同步，不能视为完全由正式镜像构建产出。
3. `docker compose build app` 在生产机上长时间卡在 Dockerfile 的 `uv sync --frozen --no-dev` 层。
4. 直接 `docker compose up -d --force-recreate app` 会回退到旧 `pythonvideo-app:latest`，导致新路由消失。

结论：

> 当前生产可用，但还不是“可重复部署”的稳定镜像态。

## 3. 本次已确认的根因

### 3.1 构建慢点

主要卡在：

```bash
RUN uv sync --frozen --no-dev
```

表现为：

- 依赖下载耗时过长
- Playwright 相关依赖体积大
- 生产机现场构建时间不可控

### 3.2 镜像标签漂移

当前 `docker compose` 实际会拉起：

```text
pythonvideo-app:latest
```

但该标签仍是旧镜像内容，不等于 `feature/yuexiang-stage2-mvp` 当前代码。

### 3.3 不能再用“代码热同步”当常态

运行容器内热同步文件虽然救火有效，但会带来：

- 镜像与代码不一致
- 后续升级不可预测
- 回滚路径不清晰

## 4. 收敛目标

目标不是“当前先能跑”，而是：

1. 用正式提交代码构建出一份可重复生成的镜像。
2. 给镜像打明确版本标签。
3. 让 `docker compose up -d app` 启动的就是这份镜像。
4. 后续升级和回滚都只围绕 Git 提交和镜像 tag 进行。

## 5. 推荐收敛路径

### 路径 A：推荐，异机构建后推镜像

这是最稳妥的方案。

#### 步骤 1：在构建机或本地构建镜像

使用分支：

```bash
feature/yuexiang-stage2-mvp
```

目标镜像 tag 建议：

```text
pythonvideo-app:stage2-5ae17ec
```

#### 步骤 2：验证镜像启动

至少验证：

- `GET /health`
- `GET /admin/ad/game-bonus-config`
- `GET /game/tasks/status`

#### 步骤 3：推送到镜像仓库

建议不要再只保留服务器本地镜像，最好推送到可拉取仓库。

#### 步骤 4：生产仅做拉镜像和重建容器

生产机执行：

```bash
cd /opt/pythonvideo
docker compose pull app
docker compose up -d --force-recreate app
curl -s http://localhost:8000/health
```

#### 步骤 5：确认后再更新稳定标签

如果运行正常，再把该版本提升为稳定版本。

### 路径 B：次优，生产机继续本地构建但先优化构建链路

如果必须在生产机构建，先做这些优化：

1. 固定 `UV_INDEX_URL`
2. 固定 `PIP_INDEX_URL`
3. 预热 Docker 基础层
4. 预热 `uv` 缓存
5. 把 Playwright 安装层单独缓存

否则会继续卡在 `uv sync` 或浏览器依赖层。

## 6. Dockerfile 改造建议

### 6.1 明确依赖源

建议在 Dockerfile 或构建环境里显式设置：

```bash
UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
PIP_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
```

### 6.2 拆分慢层

建议把下列内容尽量拆出并缓存：

- Python 基础依赖安装
- `uv sync`
- Playwright 浏览器安装

### 6.3 引入 BuildKit cache

建议为 `uv` 或 pip 缓存增加缓存挂载，减少重复下载。

### 6.4 明确镜像名

建议在 `docker-compose.yml` 的 `app` 服务中增加：

```yaml
image: pythonvideo-app:stage2-5ae17ec
```

而不是只写 `build:`。

这样生产重建时会优先使用明确镜像，而不是依赖本地旧 `latest`。

## 7. docker-compose 改造建议

目标是把“构建逻辑”和“运行逻辑”分开：

### 构建阶段

由 CI、本地、或独立构建机负责：

```bash
docker build -t pythonvideo-app:stage2-5ae17ec .
```

### 运行阶段

生产机只负责：

```bash
docker compose pull app
docker compose up -d --force-recreate app
```
