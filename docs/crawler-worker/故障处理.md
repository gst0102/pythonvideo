# crawler-worker 故障处理

更新时间：2026-06-14

## 1. 先看容器状态

```bash
cd /opt/pythonvideo
docker compose ps app crawler-worker
```

正常状态：

```text
video-service-app              Up ... (healthy)
video-service-crawler-worker   Up ... (healthy)
```

## 2. 看主服务健康

```bash
curl -fsS http://localhost:8000/health
```

正常返回：

```json
{"status":"ok","message":"服务运行正常"}
```

## 3. 看 worker 健康

```bash
docker compose exec -T crawler-worker curl -fsS http://localhost:8010/health
```

正常返回：

```json
{"status":"ok","service":"crawler-worker","chromium":"/usr/bin/chromium"}
```

## 4. 看日志

主后端日志：

```bash
docker compose logs --tail=120 app
```

worker 日志：

```bash
docker compose logs --tail=160 crawler-worker
```

## 5. 常见问题

| 问题 | 可能原因 | 处理 |
|---|---|---|
| worker 不健康 | Chromium 包缺失、启动失败、环境变量异常 | 看 worker 日志，重建 worker 镜像 |
| 主服务健康，采集失败 | worker 不通或采集站点不可访问 | 先看 worker 健康，再看采集日志 |
| LinuxDo 采集失败 | 服务器网络访问不了 LinuxDo | 使用 PC 采集导出，再后台导入 |
| KDocs 数量不对 | 文档最新日期不足 20 条 | 这是正常情况，不补旧数据 |
| 重复资源出现 | 标题规范化或网盘链接识别不足 | 进入待审核池，补充去重规则 |
| 浏览器占用过多 | 采集异常未释放浏览器 | 查看 worker 进程，必要时重启 worker |

## 6. 重启 worker

```bash
cd /opt/pythonvideo
docker compose restart crawler-worker
```

重启 worker 不会影响小程序主接口。

## 7. 重建 worker

```bash
cd /opt/pythonvideo
REV=$(git rev-parse --short HEAD)
CRAWLER_IMAGE=pythonvideo-crawler:stage2-$REV docker compose build crawler-worker
CRAWLER_IMAGE=pythonvideo-crawler:stage2-$REV docker compose up -d crawler-worker
```

## 8. 不建议做的事

- 不要因为 LinuxDo 访问失败就重启主后端。
- 不要在生产库直接清空资源表。
- 不要跳过去重规则直接批量写正式资源库。
- 不要让 worker 失败影响主 API 启动。
