# PC 导入与服务器入库流程

更新时间：2026-06-14

## 1. 什么时候用 PC 导入

以下情况建议用 PC 导入：

- 服务器访问不了 LinuxDo。
- 采集站点需要本地网络或登录状态。
- 临时批量导入运营整理好的资源。
- 想先人工检查，再决定是否入库。

PC 导入不是临时补丁，而是长期兜底方案。

## 2. 推荐流程

```text
PC 本地采集
  -> 导出 JSON / CSV
  -> PC 后台上传文件
  -> 后端解析
  -> 去重 / 分类 / 校验
  -> 自动入库或进入待审核池
  -> 生成导入记录
  -> 失败明细可下载
```

## 3. 导入结果类型

| 结果 | 说明 | 去向 |
|---|---|---|
| 成功入库 | 高置信、非重复、链接完整 | 正式资源库 |
| 进入待审核 | 低置信、疑似重复、新增网盘补充 | 后台待审核池 |
| 导入失败 | 缺少链接、字段异常、无法解析 | 失败明细 |

## 4. 导入记录

后台应能看到：

- 文件名。
- 导入时间。
- 总条数。
- 成功条数。
- 待审核条数。
- 失败条数。
- 导入状态：成功 / 部分失败 / 失败。
- 失败明细下载。

## 5. 失败不是一定代表 Bug

例如测试文件中故意放一条缺少链接的数据，结果应该是：

- 成功资源正常入库。
- 缺少链接资源进入失败明细。
- 导入记录显示“部分失败”。
- 失败 CSV 可以下载。

这是正确行为，不是系统 Bug。

## 6. 后续扩展

后续其他来源也可以共用这套导入机制：

- KDocs 手动导出。
- LinuxDo 本地采集导出。
- 运营整理的资源表。
- 合作方资源表。
- 其他项目的资源池。

核心原则：外部数据先进入统一导入层，再由后端做去重、分类、审核和入库。
