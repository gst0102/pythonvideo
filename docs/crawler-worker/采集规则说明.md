# 采集规则说明

更新时间：2026-06-14

## 1. 总原则

采集不是越多越好，第一阶段优先保证：

- 不重复入库。
- 不乱分类。
- 不把低质量资源直接展示给用户。
- 采集失败不影响主业务。
- 每次采集后浏览器进程必须关闭。

## 2. KDocs 采集

### 影视剧

- 频率：每 60 分钟一次。
- 数量：最新日期分组最多 20 条。
- 如果最新日期只有 10 条，只同步这 10 条，不补旧数据。
- 如果能识别文档里的日期，以日期为准。
- 如果不能识别日期，再走已有顺序兜底。

### 电影 / 4K影视

- 频率：每天 00:00 一次。
- 数量：最新日期分组最多 20 条。
- 同样按日期过滤，不简单相信文档前 20 条一定最新。

## 3. LinuxDo 采集

- 频率：每 12 小时一次。
- 数量：默认最新 20 条。
- 规则：规则库优先，DeepSeek 兜底。
- 高置信、链接明确、非重复：自动入库。
- 低置信、疑似重复、标题异常、链接异常：进入待审核池。
- 如果服务器无法访问 LinuxDo，不阻塞主服务，可以改用 PC 导出文件再导入。

## 4. 影视去重规则

影视资源默认跨来源去重。

优先级：

1. KDocs 官方同步资源。
2. 已上线系统资源。
3. LinuxDo 新资源。

跳过入库：

- 同标题且同网盘链接。
- 标题高度相似且链接相同。
- 规范化标题后已存在，且没有新增网盘类型。

允许补充：

- 同片名但新增网盘类型，例如已有夸克，LinuxDo 新增迅雷。

## 5. 影视积分规则

| 资源状态 | 积分 | 等级 |
|---|---:|---|
| 普通影视 / 更新中 | 5 | 普通 |
| 完结 / 全集 / 全季 / 合集 / 珍藏版 | 20 | 官方 |

判断关键词：

- 20 分：`完结`、`全集`、`全季`、`全xx集`、`合集`、`珍藏版`
- 5 分：`更08`、`更新至08`、`连载`、`持续更新`

## 6. 分类规则

一级分类：

| 分类 |
|---|
| 影视剧 |
| 自媒体素材 |
| 编程课程 |
| AI工具 |
| 电商运营 |
| 学习办公 |
| 养生健康 |
| 软件工具 |
| 本地生活 |
| 其他资源 |

二级暂不单独落库，先通过 `tags` 表达，例如：

- `Python`
- `短视频`
- `完结`
- `考研`
- `养生`
- `迅雷`

## 7. 每次采集后的要求

- 浏览器实例必须关闭。
- 失败任务要记录日志。
- 低置信结果不能直接展示给用户。
- 重复运行不能重复创建资源。
- 服务器访问失败时，不能影响主 API。
