# 网盘资源互助MVP_基于当前项目重构方案

## 1. 背景与结论

### 1.1 背景

当前项目已经沉淀了阶段二互动积分、小游戏、激励广告、支付、会员、邀请关系、二级分销、提现、积分账户、积分流水、QA 验收流程等基础能力。

新放入的两份产品文档将产品主线从“影视资源/番剧订阅/邀请解锁”调整为“网盘资料互助 + 积分解锁资源”。用户通过签到、小游戏、广告、上传资源、补链、完成求资源任务等方式赚积分，再消耗积分获取网盘资源链接。

这不是一个需要完全推倒重来的新项目，而是同一套商业底座上的资源业务域重构。

### 1.2 架构结论

建议采用：

```text
当前项目基础上重构开发
```

不建议重新另起一个完全独立项目。

原因：

1. 当前项目已有用户、积分、支付、会员、邀请、二级分销、提现等高风险基础能力，重新开发成本高且容易重复踩坑。
2. 新产品仍需要签到、小游戏、广告奖励、充值、邀请奖励、收益记录等能力，和现有底座高度重合。
3. 旧影视资源模块可以隔离为历史兼容模块，不影响新增通用资源业务域。
4. 小程序端和 PC 后台如果当前仓库没有完整工程，可以在当前仓库内新增前端目录，而不是新建后端仓库。

### 1.3 重构原则

1. 保留商业底座：登录、积分账户、积分流水、签到、小游戏、广告、支付、会员、邀请关系、二级分销、提现。
2. 隔离旧影视模块：`anime_resources`、`/anime/resources`、影视邀请解锁逻辑不继续扩展为万能资源库。
3. 新增通用资源域：统一承载网盘资料、分类、标签、获取记录、求资源、投诉、补链和后台审核。
4. 所有积分增减必须走 `user_accounts` + `points_ledger`，不得绕过流水直接改余额。
5. 所有支付、邀请奖励、提现相关逻辑按 P0 风险处理，必须幂等、可追溯、可对账。

## 2. 产品目标与 MVP 范围

### 2.1 产品定位

MVP 定位为：

```text
基于积分机制的网盘资料互助平台
```

推荐对外表达：

1. 网盘资料互助平台
2. 学习资料库
3. 办公模板库
4. 自媒体素材库
5. 团长资料库
6. 公开资料索引
7. 求资源悬赏平台

不建议在小程序名称、首页文案、审核材料和推广素材中突出：

1. 盗版影视
2. 最新影视资源
3. 盗版课程
4. 会员资源共享
5. 稳赚、保底、返佣暴利等收益承诺

### 2.2 MVP 核心闭环

第一版需要跑通以下闭环：

```text
用户登录
  -> 获得初始积分
  -> 搜索/筛选资源
  -> 消耗积分解锁网盘链接
  -> 签到/小游戏/广告/上传/补链/求资源赚积分
  -> 积分不足时充值购买
  -> 邀请好友产生邀请奖励
```

### 2.3 必须保留的现有能力

1. 小游戏保留：作为“赚积分页”的固定入口。
2. 签到保留：作为每日低门槛积分来源。
3. 激励广告保留：小游戏和广告任务都可作为积分来源。
4. 支付保留：用于购买积分、会员或后续权益套餐。
5. 会员保留：可用于资源获取次数、资源容量、专属权益、广告次数等限制。
6. 邀请关系保留：用于邀请奖励和增长。
7. 二级分销保留：底层能力保留，但前端文案建议统一为“邀请奖励/收益记录”。
8. 提现保留：用于邀请奖励提现或收益结算。

### 2.4 MVP 第一阶段范围

第一阶段必须做：

1. 用户登录与用户积分账户初始化。
2. 首页资源展示。
3. 资源列表、搜索、分类筛选、网盘筛选。
4. 资源详情，未解锁前隐藏完整链接、提取码、解压码。
5. 获取资源扣积分并生成获取记录。
6. 上传资源并进入待审核状态。
7. 后台资源审核、下架、设置精选。
8. 求资源发布，冻结悬赏积分。
9. 求资源提交与采纳，发放悬赏积分。
10. 资源失效投诉与补链。
11. 赚积分页：签到、小游戏、广告、上传、补链、求资源入口。
12. 充值积分：第一版可先支持 `10 元 = 100 积分`。

第一阶段暂缓：

1. 自动精选规则。
2. 复杂信用分。
3. AI 摘要和 AI 分类。
4. 高级搜索。
5. 多级分类。
6. 邀请排行和团队层级。
7. 复杂运营活动。

## 3. 当前项目资产盘点

### 3.1 可复用后端模块

| 模块 | 当前能力 | 重构后用途 |
|---|---|---|
| `users` | openid、邀请码、邀请关系、会员状态 | 继续作为用户主表 |
| `user_accounts` | 总积分、可提现、冻结、可消费等账户字段 | 继续作为积分资产主表 |
| `points_ledger` | 积分流水、幂等键、余额快照 | 所有资源积分增减必须写入 |
| 签到模块 | 签到积分、重复签到拦截 | 赚积分页复用 |
| 小游戏模块 | 游戏任务、广告完成、每日次数 | 赚积分页复用 |
| 广告事件模块 | 激励广告事件、完成状态、统计 | 广告赚积分、小游戏奖励复用 |
| 支付模块 | 微信支付、订单、回调幂等 | 充值积分、会员购买复用 |
| 会员模块 | 月/季/年会员、权益配置 | 可扩展为资源权益配置 |
| 邀请/佣金模块 | 一级、二级邀请收益 | 保留为邀请奖励/收益记录 |
| 提现模块 | 提现申请、冻结、成功、退回 | 邀请奖励提现复用 |
| 后台模块 | 管理端基础接口 | 扩展资源审核和投诉处理 |

### 3.2 需要隔离的旧模块

| 模块 | 当前定位 | 新方案处理 |
|---|---|---|
| `anime_resources` | 影视/番剧/4K 资源同步表 | 不作为新通用资源表继续扩展 |
| `/anime/resources` | 影视资源读取接口 | 保留兼容，后续可下线或迁移 |
| `/anime/access` | 基于邀请人数解锁影视资源 | 不进入新 MVP 主线 |
| KDocs 影视同步 | 外部影视资源同步 | 暂停作为主资源来源 |
| 番剧订阅 | 用户订阅番剧 | 与网盘资料互助主线隔离 |

### 3.3 为什么不直接改 `anime_resources`

不建议把 `anime_resources` 直接改造成通用资源表，原因：

1. 字段语义偏影视：`anime_id`、`episode`、`quality`、`four_k_url` 等会污染通用资源模型。
2. 新业务需要资源审核、积分解锁、获取记录、投诉、补链、求资源关联等完整状态机。
3. 旧接口仍可能被历史前端或脚本依赖，直接重构风险较高。
4. 新通用资源域可以更清晰地满足后台审核、合规、积分对账和 QA 验收。

## 4. 新业务架构方案

### 4.1 总体架构

```text
微信小程序端
  -> 首页 / 资源列表 / 资源详情 / 求资源 / 赚积分 / 上传 / 我的
  -> 调用 FastAPI REST API

PC 管理后台
  -> 资源审核 / 投诉处理 / 补链审核 / 分类标签 / 用户积分 / 订单收益
  -> 调用 FastAPI Admin API

FastAPI 后端
  -> 资源业务域
  -> 积分账户与流水
  -> 支付订单与回调
  -> 邀请奖励与提现
  -> 小游戏与广告奖励

PostgreSQL
  -> 现有用户/积分/支付/佣金/提现表
  -> 新增资源/求资源/投诉/补链表
```

### 4.2 小程序端信息流

```text
首页
  -> 搜索资源
  -> 网盘标签筛选
  -> 今日精选
  -> 求资源悬赏
  -> 赚积分入口

资源详情
  -> 未解锁：只展示简介、网盘类型、积分成本、验证时间
  -> 确认获取：扣积分
  -> 已解锁：展示链接、提取码、解压码、复制按钮

赚积分
  -> 签到
  -> 小游戏
  -> 激励广告
  -> 上传资源
  -> 补链
  -> 完成求资源

我的
  -> 当前积分
  -> 积分明细
  -> 我的上传
  -> 我的获取
  -> 我的求资源
  -> 邀请奖励
  -> 充值入口
```

### 4.3 PC 后台信息流

```text
资源审核
  -> 待审核资源
  -> 通过 / 驳回 / 违规下架

资源管理
  -> 搜索 / 分类 / 网盘 / 状态筛选
  -> 设置精选
  -> 设置官方合集
  -> 编辑资源

投诉管理
  -> 查看投诉
  -> 标记待确认失效
  -> 隐藏资源
  -> 要求补链
  -> 确认违规

求资源管理
  -> 查看悬赏任务
  -> 查看提交记录
  -> 处理异常争议

财务/积分
  -> 积分流水
  -> 充值订单
  -> 邀请奖励
  -> 提现记录
```

### 4.4 积分资产流

所有积分操作必须走以下路径：

```text
业务动作
  -> 生成唯一幂等键
  -> 校验账户余额/冻结余额/可消费余额
  -> 更新 user_accounts
  -> 写入 points_ledger
  -> 返回余额快照
```

禁止：

1. 直接修改用户积分但不写流水。
2. 多个业务动作共用同一个模糊幂等键。
3. 前端传入积分结果由后端直接相信。
4. 资源解锁后不生成获取记录。

### 4.5 支付与邀请奖励流

```text
用户充值积分或购买会员
  -> 创建订单
  -> 微信支付
  -> 支付回调
  -> 幂等校验 out_trade_no / transaction_id
  -> 发放积分或开通会员
  -> 根据邀请关系生成邀请奖励
  -> 奖励进入 pending / frozen / withdrawable 状态
  -> 满足结算条件后可提现
```

前端文案建议：

1. 使用“邀请奖励”。
2. 使用“收益记录”。
3. 使用“待结算/可提现”。
4. 避免“二级分销”“返佣暴利”“稳赚”等表述。

## 5. 数据模型设计

### 5.1 新增表总览

建议新增以下资源域表：

1. `resource_categories`
2. `pan_types`
3. `resources`
4. `resource_access_records`
5. `resource_requests`
6. `request_submissions`
7. `resource_complaints`
8. `resource_relinks`
9. `resource_favorites`
10. `resource_ratings`

第一阶段必须建前 8 张表，收藏和好评可放第二阶段。

### 5.2 `resource_categories`

用途：资源分类。

核心字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `name` | string | 分类名称 |
| `parent_id` | UUID/null | 父分类 |
| `sort_order` | int | 排序 |
| `status` | string | active / disabled |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

默认一级分类：

1. 影视娱乐
2. 学习资料
3. 办公模板
4. 自媒体素材
5. 团长资料
6. 软件工具
7. 电子书资料
8. 其他资源

上线时建议优先运营低风险分类：

1. 学习资料
2. 办公模板
3. 自媒体素材
4. 团长资料
5. 软件工具
6. 公开资料索引

### 5.3 `pan_types`

用途：网盘类型标签。

核心字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `code` | string | quark / baidu / xunlei / aliyun / 123pan / lanzou / tianyi / other |
| `name` | string | 展示名称 |
| `short_name` | string | 卡片短标签 |
| `sort_order` | int | 排序 |
| `status` | string | active / disabled |
| `created_at` | datetime | 创建时间 |

默认支持：

1. 夸克网盘
2. 百度网盘
3. 迅雷网盘
4. 阿里云盘
5. 123 网盘
6. 蓝奏云
7. 天翼云盘
8. 其他网盘

### 5.4 `resources`

用途：通用资源主表。

核心字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `title` | string | 资源标题 |
| `description` | text | 资源简介 |
| `category_id` | UUID | 分类 |
| `pan_type_id` | UUID | 网盘类型 |
| `link` | text | 完整网盘链接，未解锁前不得返回 |
| `extract_code` | string/null | 提取码 |
| `unzip_code` | string/null | 解压码 |
| `backup_link` | text/null | 备用链接 |
| `file_count_desc` | string/null | 文件数量说明 |
| `file_size_desc` | string/null | 文件大小说明 |
| `point_cost` | int | 获取所需积分 |
| `level` | string | normal / featured / official |
| `status` | string | pending / active / invalid_pending / hidden / offline / banned |
| `uploader_id` | UUID/null | 上传用户，官方资源可为空或平台用户 |
| `is_official` | bool | 是否官方整理 |
| `download_count` | int | 获取次数 |
| `favorite_count` | int | 收藏次数 |
| `like_count` | int | 好评数 |
| `complaint_count` | int | 投诉数 |
| `last_verified_at` | datetime/null | 最近验证时间 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

状态流转：

```text
用户上传
  -> pending
  -> 审核通过 active
  -> 表现好 featured
  -> 多人投诉 invalid_pending / hidden
  -> 补链成功 active
  -> 管理员下架 offline
  -> 违规 banned
```

### 5.5 `resource_access_records`

用途：记录用户获取资源行为，防重复扣积分和防重复给上传者奖励。

核心字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `user_id` | UUID | 获取者 |
| `resource_id` | UUID | 资源 |
| `points_cost` | int | 消耗积分 |
| `uploader_reward_points` | int | 上传者获得积分 |
| `status` | string | success / refunded / complained |
| `idempotency_key` | string | 幂等键，建议 `resource_access:{user_id}:{resource_id}` |
| `created_at` | datetime | 创建时间 |

唯一约束：

```text
同一 user_id + resource_id 只能生成一条有效获取记录
```

### 5.6 `resource_requests`

用途：求资源悬赏任务。

核心字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `user_id` | UUID | 发布者 |
| `title` | string | 求资源标题 |
| `description` | text | 需求说明 |
| `category_id` | UUID | 分类 |
| `preferred_pan_types` | JSON/list | 期望网盘类型 |
| `bounty_points` | int | 悬赏积分 |
| `frozen_ledger_id` | UUID/null | 冻结流水 |
| `status` | string | open / adopted / expired / cancelled |
| `deadline_at` | datetime | 截止时间 |
| `adopted_submission_id` | UUID/null | 已采纳提交 |
| `created_at` | datetime | 创建时间 |
| `updated_at` | datetime | 更新时间 |

规则：

1. 悬赏积分最低 5，最高 50。
2. 发布时冻结积分。
3. 采纳时发放给提交者。
4. 超时无人采纳时退回发布者。

### 5.7 `request_submissions`

用途：求资源提交记录。

核心字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `request_id` | UUID | 求资源任务 |
| `submitter_id` | UUID | 提交者 |
| `resource_title` | string | 资源标题 |
| `resource_description` | text | 资源简介 |
| `pan_type_id` | UUID | 网盘类型 |
| `link` | text | 完整链接，采纳前不得直接暴露 |
| `extract_code` | string/null | 提取码 |
| `unzip_code` | string/null | 解压码 |
| `status` | string | submitted / adopted / rejected |
| `synced_resource_id` | UUID/null | 同步入资源库后的资源 ID |
| `created_at` | datetime | 创建时间 |

### 5.8 `resource_complaints`

用途：资源失效或违规投诉。

核心字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `user_id` | UUID | 投诉用户 |
| `resource_id` | UUID | 被投诉资源 |
| `type` | string | invalid / illegal / wrong_code / low_quality |
| `description` | text/null | 投诉说明 |
| `status` | string | pending / confirmed / rejected |
| `created_at` | datetime | 创建时间 |

规则：

1. 只有已获取资源的用户才能投诉失效。
2. 同一用户对同一资源同类投诉只能有一条有效记录。
3. 1 人投诉标记为待确认失效。
4. 2 个不同用户投诉自动隐藏资源。

### 5.9 `resource_relinks`

用途：补链记录。

核心字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | UUID | 主键 |
| `resource_id` | UUID | 资源 |
| `submitter_id` | UUID | 补链者 |
| `link` | text | 新链接 |
| `extract_code` | string/null | 提取码 |
| `unzip_code` | string/null | 解压码 |
| `status` | string | pending / approved / rejected |
| `reward_points` | int | 补链奖励 |
| `created_at` | datetime | 创建时间 |
| `reviewed_at` | datetime/null | 审核时间 |

规则：

1. 上传者 24 小时内补链成功，资源恢复展示。
2. 原上传者超时未补链，可允许他人补链。
3. 他人补链审核通过后奖励 5 积分。
4. 原上传者后续分成可降低或取消，第一版可先设为“暂停原上传者分成，待人工处理”。

## 7. 积分与资金规则

### 7.1 积分账户口径

当前 `user_accounts` 已包含：

1. `total_points`
2. `withdrawable_points`
3. `frozen_points`
4. `consumable_points`
5. `consumed_points`
6. `withdrawn_points`
7. `locked_withdraw_points`

资源消费建议优先使用 `consumable_points`。如果当前前端只展示“当前积分”，应由后端统一聚合展示，避免用户误解“可提现积分”和“可消费积分”。

### 7.2 新增积分流水类型

建议新增 `points_ledger.change_type`：

| 类型 | 说明 | availability |
|---|---|---|
| `resource_access_cost` | 获取资源扣积分 | consumable |
| `resource_upload_reward` | 上传审核通过奖励 | consumable |
| `resource_download_reward` | 资源被获取后上传者奖励 | consumable |
| `resource_request_freeze` | 发布求资源冻结悬赏 | frozen |
| `resource_request_adopt` | 采纳后发放悬赏 | consumable |
| `resource_request_refund` | 求资源超时/取消退回 | consumable |
| `resource_relink_reward` | 补链成功奖励 | consumable |
| `resource_violation_penalty` | 违规或失效扣分 | consumable |
| `points_recharge` | 充值积分到账 | consumable |

### 7.3 初始积分

新用户注册后获得 100 积分。

限制：

1. 初始积分只进入可消费积分，不进入可提现积分。
2. 新用户前 24 小时最多获取 5 个资源。
3. 初始积分不可转赠。
4. 异常账号可限制下载和上传。

### 7.4 资源获取扣积分

MVP 三档：

1. 普通资源：5 积分。
2. 精选资源：10 积分。
3. 官方合集：20 积分。

扣积分规则：

```text
用户确认获取资源
  -> 检查是否已获取
  -> 检查资源状态 active / featured / official
  -> 检查 consumable_points 是否足够
  -> 扣除积分
  -> 写 resource_access_records
  -> 写 points_ledger
  -> 返回完整链接、提取码、解压码
```

幂等键建议：

```text
resource_access:{user_id}:{resource_id}
```

### 7.5 上传者下载分成

普通资源：

```text
下载者扣 5 分
上传者得 1 分
平台回收 4 分
```

精选资源：

```text
下载者扣 10 分
上传者得 2 分
平台回收 8 分
```

官方合集：

```text
下载者扣 20 分
平台获得全部积分
如果官方合集来自用户投稿，可一次性奖励用户 20 分
```

防刷规则：

1. 同一用户获取同一资源，只奖励上传者一次。
2. 单个资源每日下载奖励上限 10 分。
3. 新用户前 24 小时获取行为不计入热门升级。
4. 异常设备、多账号互刷进入风控观察。

### 7.6 求资源冻结与发放

发布求资源：

```text
检查 bounty_points 在 5 - 50
检查 consumable_points 足够
冻结 bounty_points
写 resource_request_freeze 流水
创建 resource_requests
```

采纳提交：

```text
校验请求状态 open
校验提交记录有效
将冻结积分发给提交者
写 resource_request_adopt 流水
更新 resource_requests.status = adopted
可选择同步为 resources
```

超时或取消：

```text
退回冻结积分给发布者
写 resource_request_refund 流水
更新状态 expired / cancelled
```

### 7.7 小游戏和广告积分

小游戏保留，但新产品口径调整为：

```text
玩一把小游戏并完整观看激励广告，获得固定积分奖励
```

建议第一版：

1. 每次 +2 积分。
2. 每天最多 3 次。
3. 每日最高 6 积分。
4. 失败游戏、广告未完成、重复回调均不得发积分。

如果继续保留阶段二 eCPM 结算能力，应放入后续版本，不建议作为网盘资源互助 MVP 第一阶段主线。

### 7.8 支付与充值积分

第一版建议：

```text
10 元 = 100 积分
```

支付规则：

1. 创建充值订单。
2. 微信支付成功回调后发放可消费积分。
3. 同一 `out_trade_no` 只能发放一次。
4. 支付失败不发积分。
5. 退款场景必须定义是否扣回积分；如果积分已消费，需要进入人工处理或形成负债记录。

### 7.9 会员与邀请奖励

会员保留，可作为后续增强：

1. 每日资源获取次数提升。
2. 上传资源数量提升。
3. 高级搜索。
4. 免广告次数。
5. 专属资源合集。

邀请奖励保留：

1. 基于真实支付订单触发。
2. 支持一级、二级邀请收益。
3. 支付回调必须幂等。
4. 退款后奖励必须失效或回滚。
5. 前端文案叫“邀请奖励”，不突出“二级分销”。

## 9. 高风险点与验收重点

以下全部按 P0 处理。

### 9.1 积分风险

1. 获取资源重复扣积分。
2. 获取资源重复奖励上传者。
3. 扣积分成功但未展示链接。
4. 展示链接成功但未扣积分。
5. 积分余额和流水不一致。
6. 求资源冻结后未写流水。
7. 采纳后悬赏重复发放。
8. 求资源超时未退回冻结积分。
9. 补链奖励重复发放。
10. 上传审核通过重复奖励。

### 9.2 资源泄露风险

1. 未解锁用户看到完整链接。
2. 接口返回中泄露链接字段。
3. 分享页面绕过解锁直接访问。
4. 求资源提交在采纳前泄露链接。
5. 后台权限不足用户可查看链接。

### 9.3 小游戏和广告风险

1. 游戏失败也发积分。
2. 广告未完整观看也发积分。
3. 同一局游戏重复发积分。
4. 重复广告回调重复发积分。
5. 每日次数限制不生效。
6. 广告曝光/完成统计错误。

### 9.4 支付和邀请奖励风险

1. 支付成功但积分未到账。
2. 支付失败却发积分。
3. 重复支付回调导致重复发积分。
4. 支付成功但邀请奖励未生成。
5. 二级邀请奖励比例错误。
6. 退款后奖励未失效。
7. 邀请奖励重复结算或重复提现。
8. 用户自己邀请自己。
9. 重复绑定邀请人。

### 9.5 内容合规风险

1. 未授权影视资源传播。
2. 盗版课程传播。
3. 会员资源共享。
4. 违规链接。
5. 低质量失效链接泛滥。
6. 恶意投诉。
7. 多账号刷积分。
